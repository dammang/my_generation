# V1

## R2_URL must stay empty; a custom domain publishes the whole bucket
An R2 custom domain serves every object in its bucket anonymously — not just the ones the app marks public. Attaching media.khanggui.com to the bucket holding private media made every private photograph fetchable by anyone with its path, and the path is the readable half of every signed URL ever issued. Verified in production: objects came back byte-identical with no credentials.

So R2_URL stays empty unless a SEPARATE public-only bucket exists. With it empty, MediaUrlResolver signs everything (15 min); it only uses a public base when that disk's `url` is genuinely configured, and it returns null rather than falling back to an unsigned path.

Trap when removing such a domain: R2 owns its DNS record. Deleting the record in the DNS tab does not stick while the custom domain is still attached — remove it in R2 → bucket → Settings → Custom Domains, and R2 removes the record itself. Check the r2.dev public dev URL separately; it is a second, independent exposure.

Prove closure from outside, not from the dashboard: upload a fresh object (paths are content-addressed, so a new file has a never-before-seen key), then fetch it over the public host. A cache-busted 200 means the binding is live; cf-cache-status alone proves nothing.
